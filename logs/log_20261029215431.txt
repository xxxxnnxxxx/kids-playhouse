二、空白页根因分析（已用 node 复现，证据确凿）
====================================================================
web/src/router.ts 的 dispatch() 把路径归一化为 "/"（带斜杠的字符串），
而 route('/') 注册生成的正则是 "^$"（空串），二者永不匹配；
于是走 fallback → main.ts 里 fallback 是 navigate('/') → 再 dispatch('/') →
仍不匹配 → 同步无限递归 → JS 栈溢出，renderHome 从未执行，页面空白。
之前 curl 冒烟只验证了 HTML 200（外壳），未执行 JS，所以没暴露；
且工作区规范禁止用浏览器测试，故当时未发现。

====================================================================
三、修复方案（对现有代码影响极小）
====================================================================
1. router.ts：dispatch() 归一化去掉 "|| '/'"，根路径归一化为空串，恰好命中 "^$"；
   其余路径行为不变（/html5、/play/xxx 均不受影响）。
2. main.ts：fallback 改为直接渲染首页（不再 navigate），从设计上杜绝任何
   pushState 死循环的可能。
3. 修复后验证：node 复跑路由命中测试（'/'、'/html5'、'/play/snake'、
   未知路径→渲染首页）；重新 npm run build；起服务 curl 首页与 SPA 路由 200。
   不使用浏览器（遵守工作区规范）。

====================================================================
四、Makefile 方案
====================================================================
新增根目录 Makefile（GNU Make，Windows 下在 Git Bash 里执行 make，
或 mingw32-make；脚本显式 SHELL=bash，保证 rm/cp 等 Unix 命令可用）：

- make / make all ：一键构建，产物全部进入 output/：
    output/server.exe（Windows）/ server（Linux/macOS）  ← go build ./server
    output/web/dist/                                    ← Vite 编译产物拷贝
    output/games/                                       ← 游戏清单与资源拷贝
- make run      ：构建完成后直接在 output/ 内启动服务（默认参数
                  -web web/dist -games games 相对 exe 所在目录恰好命中），
                  打开 http://localhost:8080 即可。
- make clean    ：删除 output/ 与 web/dist。

影响说明：不改变任何现有源码结构；.gitignore 增加 output/；
README 的"快速开始"同步补充 make 用法。
