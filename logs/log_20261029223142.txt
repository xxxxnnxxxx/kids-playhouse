主题：优化 Python 游戏播放页布局（画布/终端/发送框/代码窗口）（等待用户确认）

====================================================================
一、用户反馈（复述）
====================================================================
Python 游戏页面里，游戏窗口（画布）、发送窗口（终端及输入行）、
代码窗口三个区域的布局不好看；"发送窗口"对有的游戏根本用不上，
或者不需要占那么大一块。希望优化布局。

====================================================================
二、现状问题分析
====================================================================
当前布局对所有 Python 游戏一刀切：右侧固定 320px 高的深色终端
（永远带一行输入框）+ 下方默认收起的代码编辑器。导致：
1. 贪吃蛇/海龟画图根本不用"发送"输入行（蛇靠键盘、海龟无交互），
   却占着显眼位置；终端对它们只是打印日志/报错，320px 偏大；
2. 猜数字机器人的主战场就是终端，却只有 320px，显得小；
3. 代码编辑器藏在按钮后面，海龟画图"改代码"才是核心玩法却不直观。

====================================================================
三、优化方案：按游戏类型自适应布局
====================================================================
【画布类游戏（贪吃蛇、海龟画图）】
┌─────────────────────────────┬─────────────┐
│         游戏画布（左，大）      │ main.py     │
│                             │ 代码编辑器    │
│                             │(海龟默认展开/ │
│                             │ 蛇默认收起)   │
├─────────────────────────────┴─────────────┤
│ ▸ 终端输出（紧凑条 ~140px，可折叠，无输入行）    │
└───────────────────────────────────────────┘
- 终端降级为"日志条"：只显示 print 输出与报错；报错时自动展开；
- 输入行默认隐藏，只有当运行的代码真的定义了 on_input 才显示
  （运行时动态判断，改代码加交互也即时生效）。

【控制台游戏（猜数字机器人）】
┌───────────────────────────────────────────┐
│ 终端（主角，加大到 ~440px，输入行常驻）          │
├───────────────────────────────────────────┤
│ 代码编辑器（默认收起，"看代码"展开）             │
└───────────────────────────────────────────┘
- 画布隐藏（沿用现有 canvas:false 标记）。

【实现要点】
1. games/games.json：Python 游戏条目增加 "editorOpen" 字段
   （海龟 true，其余 false，控制每款游戏代码区默认展开与否）；
   server/games.go 的 Game 结构体加对应字段透传；
2. web/src/pyodideRunner.ts：按 game.canvas 加布局修饰类
   （--canvas / --console）；输入行按 on_input 存在与否动态显隐；
   终端加"折叠/展开"；按钮文案 看代码↔收起代码 切换；
3. web/src/styles.css：两种布局样式 + 窄屏(<960px)纵向堆叠；
4. 不改任何游戏玩法代码、不改后端路由；npm build + make 重建 +
   output/ 启动 curl 冒烟（规范内验证，不用浏览器）。
