主题：修复"海龟画图小画家页面显示成贪吃蛇"（等待用户确认）

====================================================================
一、用户反馈（复述）
====================================================================
Python 游戏里打开"海龟画图小画家"，页面显示的内容却和贪吃蛇一样——
看到的是贪吃蛇而不是海龟画图。

====================================================================
二、根因（已用本地 CPython 复现证实）
====================================================================
Pyodide 运行时在整站是单例（只加载一次，这是合理的），但每次"运行"
都在同一个 Python 全局命名空间（pyodide.globals）里执行代码。
先玩过贪吃蛇后，蛇的 setup/update/on_key 会永久残留在命名空间里；
再打开海龟画图点"运行"：海龟代码先画出星星彩虹，随后运行器启动
引擎时发现命名空间里"存在 update/on_key"（其实是贪吃蛇留下的），
于是每帧调用贪吃蛇的 update/draw —— 画布立即被贪吃蛇整体重绘覆盖，
海龟作品一闪而过，用户看到的就是一条活的贪吃蛇。
复现输出：海龟代码运行后 setup/update/on_key 均残留，且引擎随后
每帧产生贪吃蛇的 clear/rect 绘制调用。

====================================================================
三、修复方案
====================================================================
让每次"运行"都在全新的 Python 命名空间中执行（隔离）：
1. pyodideRunner.ts：运行时用 py.toPy({}) 新建命名空间字典，
   runPython(PYTHON_PRELUDE, {globals: ns}) 与
   runPythonAsync(代码, {globals: ns}) 都指定该命名空间；
2. 引擎读取 setup/update/on_key/on_input 改从该命名空间取，
   不再读共享的 pyodide.globals —— 旧游戏的回调天然不可能残留；
3. 新一次运行前销毁上一次的命名空间 PyProxy（先 stopEngine 再销毁，
   防止内存泄漏）；
4. 术语说明：不影响 turtle/webgames 模块注册（sys.modules 属于解释器级，
   正常保留，无需每次重建）。

影响范围：仅 web/src/pyodideRunner.ts 一个文件；三款 Python 游戏源码、
其他页面均不动。验证方式：本地 CPython 重放"先蛇后海龟"场景确认
新命名空间下海龟页面不再出现贪吃蛇回调与绘制；npm run build 通过；
make 重建后从 output/ 启动 curl 冒烟（遵循规范不使用浏览器）。
